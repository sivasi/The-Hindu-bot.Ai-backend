═══════════════════════════════════════
WHY THIS MATTERS
═══════════════════════════════════════
- Site is HTTPS: https://the-hindu-bot.netlify.app
- API is HTTP NodePort: http://34.93.159.106:30001
- Browsers BLOCK https → http (mixed content).
- Backend CORS allows: https://the-hindu-bot.netlify.app
- Google does NOT allow IP redirect URIs — use GIS idToken flow only (no /api/auth/google/callback).

Frontend MUST call same-origin `/api/...`; Netlify proxies to GKE.

3) GOOGLE SIGN-IN (Option A — GIS only)
═══════════════════════════════════════
Google Cloud Console → OAuth Web client:
  Authorized JavaScript origins:
    https://the-hindu-bot.netlify.app
    http://localhost:5173
  Authorized redirect URIs:
    leave empty OR if required use frontend only:
    https://the-hindu-bot.netlify.app
    http://localhost:5173
  DO NOT use http://34.93.159.106:30001/...

UI: require Google sign-in before Ask / PDF.

Load script:
  https://accounts.google.com/gsi/client

Example (Sign In With Google → exchange credential for app JWT):

  function handleGoogleCredential(response) {
    // response.credential is the Google ID token
    return fetch(`${import.meta.env.VITE_API_URL}/api/auth/google`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ idToken: response.credential }),
    }).then((r) => r.json()).then((data) => {
      // data.token = app JWT; data.user = Mongo user; data.created = bool
      localStorage.setItem("rag_token", data.token);
      return data;
    });
  }

  // Initialize button / One Tap with client_id = VITE_GOOGLE_CLIENT_ID
  // callback: handleGoogleCredential

On logout: clear localStorage token; optional POST /api/auth/logout.

All protected API calls must send:
  Authorization: Bearer ${localStorage.getItem("rag_token")}

PDF iframe (cannot send Authorization header):
  `${VITE_API_URL}/api/manual?token=${encodeURIComponent(token)}#page=${pageNumber}`

Optional: GET /api/auth/me with Bearer token to restore session UI.
Optional: GET /api/auth/config → { clientId } if you prefer loading client id from API.

4) CHAT HISTORY (ChatGPT / Gemini style)
═══════════════════════════════════════
Layout like ChatGPT:
- Left sidebar: list of chat sessions (each = one “box” / conversation)
- Main pane: messages for the active session (user + assistant turns)
- Top: “New chat” button → clears main pane / creates empty session
- Clicking a sidebar item loads that session’s messages
- Rename / delete session from sidebar (⋯ menu)

APIs (all need Authorization: Bearer <jwt>):

GET    /api/chats
→ { sessions: [{ id, title, preview, messageCount, lastMessageAt, createdAt }] }
  Sort newest first — render as sidebar rows (title + preview + relative time).

POST   /api/chats
Body optional: { "title": "New chat" }
→ { session }

GET    /api/chats/:id
→ { session, messages: [{ id, role: "user"|"assistant", content, sources?, meta?, createdAt }] }
  Render messages in order like a chat thread.

PATCH  /api/chats/:id
Body: { "title": "Renamed title" }
→ { session }

DELETE /api/chats/:id
→ { ok: true }

Saving turns (automatic on Ask):
POST /api/query/stream
Body:
{
  "question": "...",
  "mode": "normal" | "turbo_short" | "turbo_research",
  "sessionId": "<optional — omit or null for first message in a New chat>"
}

SSE event order:
  status… → (token…) → result → session → done

On type=session:
  { "type":"session", "sessionId":"...", "session":{...}, "created": true|false }
  - Store sessionId in state for the next Ask in this thread
  - If created, prepend/update sidebar with session
  - Always refresh sidebar title/preview from event.session

On type=result: append assistant message (and you already showed user message optimistically).

“New chat” UX:
  1) Clear activeSessionId + messages in UI
  2) Optional: POST /api/chats for an empty box, or wait until first Ask (backend creates session if sessionId omitted)
  3) Next Ask without sessionId creates a new sidebar entry titled from the question

Do NOT mix messages from different sessionIds in one thread.
